## Final design for 100,000 users (provisional; under two pages)

**Input extraction: hybrid.** Validate structured fields with deterministic types and ranges. Use Gemini for flexible language extraction only after that path has been measured. Missing, contradictory or unsupported information returns clarifying questions; no liability is produced until resolved. Cache static rule text, not private user descriptions.
**Tax arithmetic and recommendation: rules.** The two deterministic paths agree on the frozen suite and are repeatable in this experiment. An LLM does not earn a per-request arithmetic role on the present evidence. Compare both computed liabilities; report a tie rather than fabricating a preference. Use decimals and statutory rounding.
**Legal updates: hybrid authoring, deterministic execution.** An LLM may propose declarative changes. A reviewer compares official clauses, inspects a typed diff, adds independent boundary cases, checks the official calculator and signs the release. Candidates cannot auto-promote. Pin FY plus rule hash in the response and retain the arithmetic trace. Roll back a release without changing historic rule versions.
**Operations: rules and human release controls.** Deploy a stateless service with authenticated access, input-size limits, no taxpayer text in routine logs, and traces tied to request IDs. 100,000 users is not an RPS specification; load-test the expected peak concurrency, measure parser quotas and use a queue/circuit breaker for Gemini. Missing extraction service should return a structured form, not a guessed answer.
**Next Budget:** keep old rules immutable, ingest only named official provisions, add threshold tests before promotion, run both old and candidate rules in shadow mode, then release the new FY after calculator validation. This is not yet a production tax service: official verification, legal review, Gemini evidence, peak-load tests and the requested contemporaneous migration record remain outstanding.
