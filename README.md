# Rules vs LLMs — FireAI take-home

Two Python experiments comparing deterministic rules, fitted statistical checks
and LLM review. This repository contains working offline implementations and
measured evidence, plus opt-in Gemini experiments. **It is not yet a fully
completed assignment:** the official-calculator checks and Gemini measurements
are outstanding. See [SUBMISSION_CHECKLIST.md](SUBMISSION_CHECKLIST.md).

## Run the current evidence

Python 3.10+; no third-party packages are required for the offline pipeline.
From this directory:

```bash
python reproduce.py
```

That verifies the dataset/fixture hashes, runs the regression tests, benchmarks
both projects and regenerates these required reports:

- [RESULTS_A.md](RESULTS_A.md): tax accuracy, repetition, latency, source traces,
  stale-law simulation and provisional shipping design.
- [RESULTS_B.md](RESULTS_B.md): real-data findings, all 36 family/problem slots,
  held-out detector results, hybrid and scale design.
- [DECISION_MATRIX.md](DECISION_MATRIX.md): measured component decisions.
- [AI_USAGE.md](AI_USAGE.md): AI contributions, a corrected error and limitations.

Timings vary by machine. To recreate the exact tables from the checked-in raw
measurements while still running tests:

```bash
python reproduce.py --replay
```

To refresh the public 2023 data (network required), benchmark and regenerate:

```bash
python reproduce.py --download
```

The committed 12,000-row snapshot samples the first ordered quota in each of
2023's 12 months. It is not the entire dataset or a probability sample. Queries,
retrieval timestamp and SHA-256 are in `data/nyc311_2023.manifest.json`.

## Project A: try the calculator

```bash
python -m project_a.cli --input examples/tax.json
python -m project_a.cli --text "Meri salary 12 lakh hai aur rent 15000 hai."
python -m project_a.cli --text "FY 2024-25. age 30. Indian tax resident. Annual gross salary INR 1500000. All other claims are zero."
```

The first command returns both regimes, a recommendation/tie and calculation
traces. The second asks clarifying questions. The third supplies enough explicit
facts for the conservative rule parser. Add `--llm-parser` for Gemini extraction
after configuring credentials.

All monetary inputs are **annual INR**. `gross_salary` means taxable gross salary
before the scoped exemptions/deductions, not CTC or take-home. Structured API
zero defaults are documented in `model.py`; free text must explicitly confirm
omitted claims are zero. HRA inputs must cover a consistent rental period;
changes in rent/city/pay require separate period calculations and review.
Self-occupied home-interest eligibility must be confirmed, not guessed.
`self_group_senior`/`parents_senior` mean a qualifying resident senior in that
insurance group. Premium inputs are already eligible non-cash amounts. The
current model conservatively rejects mixed insured/uninsured medical-expense
groups instead of attempting an unsupported person-by-person allocation.

Supported FYs: 2024-25 and 2025-26. The engines handle the scoped standard
 deduction, HRA, 80C, additional 80CCD(1B), 80D, self-occupied home interest,
87A and marginal rebate relief, surcharge with marginal relief, cess and
288A/288B rounding. Unsupported income/deductions and tax credits need an
extended model; this is annual liability, not a filing/refund utility.

Implementations:

1. `project_a/handwritten.py`: directly authored deterministic tax operations.
2. `project_a/llm_runtime.py`: Gemini reads the versioned extract and calculates
   at query time. No deterministic answer is substituted.
3. `project_a/compiled_rules.py`: fixed interpreter for reviewed LLM-produced
   declarative JSON. The committed configurations were generated by Codex,
   **not Gemini**. Gemini candidate generation is separately available and
   cannot auto-promote. The interpreter itself is handwritten.

Frozen fixtures contain 2,296 taxpayer cases with expectations under both
regimes, from an independent closed-form test oracle. They are regression
fixtures, **not 2,296 official-calculator checks**. The official evidence
register has 30 distinct cases, each with both-regime checks still pending.

## Project B: pipeline and evaluation

`download.py` -> `profile.py` -> train/validation/test split -> `inject.py` ->
`detectors.py` -> validation-selected `hybrid.py` -> benchmark reports.

Twelve corruption types are implemented: schema rename/drop; numeric type
change; mid-batch timestamp-format switch; swapped coordinates; exact and near
duplicates; agency-specific descriptor null spike; reversed dates; ZIP/borough
mismatch; complaint/descriptor mismatch; resolution/status contradiction; and
fictional phone/email/name text.

The schema/type/date statistical baselines overlap with deterministic contracts;
this is acknowledged rather than presented as sophisticated ML. Association
checks learn only from the named dataset. No external ZIP database or name list
is used. Schema events are batch-level; null spikes are agency-group events.
Other metrics have row-level denominators. Both row and batch rates are reported.

Labels from controlled injections are known. Semantic correctness of unmodified
held-out source rows is **not independently adjudicated**: clean flag rates are
proxy false-alarm rates. The documented corruption templates are deliberately
limited. Results cannot establish recall on arbitrary real-world corruption.

## Gemini: opt-in, bounded live runs

No API key belongs in Git, an uploaded source file, a screenshot or chat.
Choose a currently available free-tier Gemini model in your own account and set
its exact model identifier. Availability/rate limits are account dependent.

Windows PowerShell:

```powershell
$env:GEMINI_API_KEY = "YOUR_LOCAL_KEY"
$env:GEMINI_MODEL = "YOUR_AVAILABLE_MODEL_ID"
python live_experiments.py --max-calls 300 --tax-limit 30 --b-rows 120
python reproduce.py --replay
```

Linux/macOS:

```bash
export GEMINI_API_KEY='YOUR_LOCAL_KEY'
export GEMINI_MODEL='YOUR_AVAILABLE_MODEL_ID'
python live_experiments.py --max-calls 300 --tax-limit 30 --b-rows 120
python reproduce.py --replay
```

This bounded run is **partial** tax-suite coverage, 50 parser examples, ten
repetitions of the same taxpayer per regime, two compilation candidates, all
12 detector categories on a smaller clean/corrupted sample, and optional hybrid
review. Token usage, latency and failures are retained. Errors and exhausted
budgets do not fall back to mocked successes. No automatic retries run.

Full tax-suite coverage requires `--tax-limit 2296` and an explicitly adequate
`--max-calls`/free-tier quota; do not claim a 30-case run evaluates all 2,296.
The LLM data-quality run has fewer seeds/rates than the offline benchmark; extend
that experiment before claiming a matched head-to-head comparison.

To estimate paid-equivalent costs, set verified current
`GEMINI_INPUT_USD_PER_MILLION` and `GEMINI_OUTPUT_USD_PER_MILLION`. Actual
free-tier charges and projected paid cost are different. CPU/storage costs need
separate measurements. The `common.token_cost` helper includes reported thinking
tokens but failed-call token costs may be unknown.

Live evidence is under ignored `results/live/` so raw model outputs and accidental
secrets cannot be committed automatically. Review and explicitly include a
sanitized evidence snapshot before sharing. Do not merely share local ignored
results and claim the private repo reproduces them.

## Submission and integrity

```bash
python reproduce.py --strict
```

This intentionally exits nonzero while required evidence is missing. A passing
offline test run is not a declaration that the whole assignment is complete.
Test-first chronology and human update timings were not recorded and must not
be invented. Keep the repo **private**, give the actual hiring-team accounts
access, and only then complete the registration as instructed by the campus
notice. No registration or reviewer invitation is performed by this code.

Start interview review with [WALKTHROUGH.md](WALKTHROUGH.md). Read every function,
rerun examples and practise changing a rule/check before submitting.
